# Implementation plan

## Open tasks

### RL-024 — [FEAT] Read a library folder through config.txt

- Dependency: None.
- Why: The owner wants RigLab's rigs, skins, weapons and animations to come from one folder outside the repository, mapped by a `config.txt`, and wants that folder to be the starting library new documents are seeded from. Today they are compiled in from `characters/` through fixed imports in `src/chibi/chibi.ts` and `src/weapons/weapons.ts`, palettes are hard-coded in `src/app/styles.css`, and there are no animation files at all. The repository keeps placeholder files shaped exactly like the real folder so tests and CI exercise the same ingest path.
- Scope: Add the library contract and a pure loader, with no app change yet. `config.txt` is UTF-8 text: blank lines and `#` comments are ignored, and every other line is `<kind> <name> = <path>`. `kind` is `rig`, `skin`, `weapon` or `animation`, `name` is a RigLab name, and `path` is relative to the folder, uses `/` and never contains `..`, a leading `/` or a `\`. Line order is list order. A library has exactly one `rig` line naming a `riglab.rig` file. A `skin` line names a directory holding one part SVG per rig slot, named after the slot without its first `_`-separated prefix (`chibi_arm_lower_l` → `arm_lower_l.svg`), plus a `palette.json`. A `weapon` line names a directory holding `weapon.json` (`riglab.weapon` version 1, valid for the rig), one part SVG per body slot under the same naming rule, a `palette.json`, and, when the weapon has free bodies, a `hold.json` placing each free body for its first hold. That moves the ready holds out of `src/weapons/weapons.ts` and into data. An `animation` line names a `riglab.anim` version 2 file valid for the rig and the library's weapons. Add a closed `riglab.palette` version 1 format in `src/format/palette.ts`. It maps class tokens to `fill`, `stroke`, `strokeWidth`, `opacity` and `linecap`, with colors as `#rrggbb` or `none`, plus an optional `pixel` flag. `paletteCss` turns a validated palette into CSS scoped to `.art-set--<name>`, so the generated text never comes from unvalidated input. Every part goes through the existing strict `parsePart`, its `data-bone` must be the bone that owns the slot (or the body's name, for weapons), and every class token it uses must be defined in its palette. Each skin's and weapon's art set is its own config name. `loadLibrary(files)` takes config-relative paths to file text and returns the rig, skins, weapons with their parts, palettes and holds, and animations, all in config order. Every error names its `config.txt` line or file path. Add `placeholder-library/` with a `config.txt`, a `README.md`, the current chibi rig and the four current weapon rigs copied unchanged, two complete placeholder skins of plain one-path shapes in distinct palettes, a plain bar or blade part for each weapon, the four ready holds from today's code, and one rest-pose animation per kind (idle, walk, jump, attack, hit) on Hexframe's grid.
- Non-goals: Wiring the editor, Vite or the real folder (RL-025), PR 15's skins (RL-026), the wardrobe page (RL-027), more than one rig per library, and partial skins.
- Acceptance: The placeholder library loads with no errors, and its rig and weapons equal today's `CHIBI_RIG` and `WEAPONS`. Config tests refuse each of the following with its line number: an unknown kind, a bad name, a duplicate name within a kind, a missing or second rig, a path with `..`, `\` or a leading `/`, and a line without `=`. Loader tests refuse a skin with a missing or extra slot file, a part whose `data-bone` is the wrong bone, an undefined class token, a palette with an unknown field or a bad color, a weapon whose hold does not match its free bodies, and an animation for another rig. Each refusal names the file. `paletteCss` scopes every rule to its set and emits only validated values. `npm run check` passes.
- Validation: Pinned `npm ci`, focused format and loader tests, `npm run check`, `npm run audit:dependencies`, `check:patch`, `git diff --check`, and exact-head CI.
- Authorities: `src/hexframe/parts.ts`, `src/format/rig.ts`, `src/format/weapon.ts`, `src/format/animation.ts`, `src/format/validate.ts`, `src/editor/animations.ts`, `src/weapons/weapons.ts`, `src/app/styles.css`, `docs/ARCHITECTURE.md`, and owner direction on 2026-10-13.

### RL-025 — [FEAT] Seed the editor from the library folder

- Dependency: RL-024.
- Why: With the loader in place, the editor must take its rig, art, weapons and starting animations from the owner's folder instead of from `characters/`, and that folder must hold the real assets.
- Scope: Add a Vite plugin that serves a virtual library module to the dev server, the build and Vitest. It picks the folder named by `RIGLAB_LIBRARY`, else `~/Documents/RigLab/` when that folder holds a `config.txt`, else `placeholder-library/`. It reads `config.txt` and only the files its lines map, and refuses any path that resolves outside the folder (symlinks included), any file type other than `.txt`, `.json` and `.svg`, and any oversized file. Under `npm start` it watches the folder and reloads the page when a mapped file or `config.txt` changes. A library that fails to load shows the loader's errors in Vite's overlay instead of a broken editor. Vitest and `npm run check` always use the placeholder, so checks behave the same on every machine. `src/chibi/chibi.ts`, `src/weapons/weapons.ts` and `src/editor/templates.ts` read the loaded library. The editor draws with the first skin in `config.txt`, picks weapons in config order at their `hold.json` placements, and starts a new document with the rig and the library's animations. Saving and opening still use one `.riglab.json` file. The hard-coded chibi and weapon palettes leave `src/app/styles.css` and are emitted from the palettes. The status bar names the library in use, home-relative, or says it is the placeholder. Add `npm run check:library [folder]`, a local-only validation of a real folder that is not part of `check`. Remove `characters/`. Port the real assets into `~/Documents/RigLab/` outside git: the chibi rig, the 11 original chibi parts as skin `chibi`, the four weapon rigs and their art, palettes converted from today's CSS, the four ready holds, and one rest-pose animation per kind. That folder then passes `check:library`. Update the README and architecture docs.
- Non-goals: PR 15's skins (RL-026), the wardrobe page (RL-027), a skin picker in the editor, saving into the folder, versioning or backing up the real folder, and changing the document, animation or weapon formats.
- Acceptance: Every existing editor, export and acceptance test passes against the placeholder library. Tests that assumed an empty starting document now expect the five seed animations, and the weapon acceptance runs keep their bounds. Plugin tests refuse a `..` or symlink escape, an unmapped file type and an oversized file. They also pick `RIGLAB_LIBRARY`, then the home folder, then the placeholder. `npm run check:library ~/Documents/RigLab` passes. On a headless Chrome pass against `npm start` with the real folder, the editor draws the original chibi art, holds each of the four weapons, lists the five seed animations, and shows the library's name in the status bar, with no console errors. Editing a part SVG in the folder reloads the page with the new art. `npm run check` passes.
- Validation: Pinned `npm ci`, focused plugin and editor tests, `npm run check`, `npm run check:library`, `npm run audit:dependencies`, `check:patch`, `git diff --check`, a headless Chrome pass on a worktree dev server, and exact-head CI.
- Authorities: `vite.config.ts`, `vitest.config.ts`, `package.json`, `src/chibi/chibi.ts`, `src/weapons/weapons.ts`, `src/editor/templates.ts`, `src/app/styles.css`, `src/app/StatusBar.tsx`, `README.md`, `docs/ARCHITECTURE.md`, and owner direction on 2026-10-13.

### RL-027 — [FEAT] Add a /wardrobe/ page that cycles every skin and part

- Dependency: RL-025 and RL-026.
- Why: The owner wants a `/wardrobe/` route to step through each skin and each part in the library.
- Scope: Add `wardrobe/index.html` and `src/wardrobe/` as a second Vite page, served at `/wardrobe/` by `npm start` and built to `dist/wardrobe/index.html`. The editor's toolbar links to it and it links back. The page draws the library's rig large with art on, read-only, reusing `RigCanvas` and the art layer without handles. Skin ‹ › puts one skin on every slot. Each of the rig's slots has its own ‹ › that cycles that slot's part through every skin and shows which skin it came from, so parts mix and match. Weapon ‹ › cycles None and each library weapon at its hold. Motion ‹ › cycles Rest and each library animation, played in a loop through the existing playback, so skins can be checked at rotated joints. Arrow keys step skins (←/→) and slots (↑/↓), `[` and `]` cycle the selected slot's part, and Reset puts the current skin back on every slot. All of this lives in a pure state module.
- Non-goals: Saving an outfit to documents or carrying it into the editor (the owner chose browse-only on 2026-10-13), editing art, export, and remembering the selection between visits.
- Acceptance: State tests cycle skins, slots, parts, weapons and motions with wraparound in both directions, keep every slot mapped to a library skin, and reset. On headless Chrome at `/wardrobe/`, against the placeholder library and then the real folder, every skin and every slot's parts are stepped through. At each step the drawn parts come from the expected art sets with one part per slot. Weapons and motions cycle, and there are no console errors. The editor at `/` is unchanged, and `npm run build` emits both pages. `npm run check` passes.
- Validation: Pinned `npm ci`, focused wardrobe state tests, `npm run check`, `npm run audit:dependencies`, `check:patch`, `git diff --check`, the headless Chrome pass on a worktree dev server, and exact-head CI.
- Authorities: `vite.config.ts`, `index.html`, `src/app/Toolbar.tsx`, `src/viewer/RigCanvas.tsx`, `src/viewer/ArtLayer.tsx`, `src/viewer/usePlayback.ts`, `docs/ARCHITECTURE.md`, and owner direction on 2026-10-13.
