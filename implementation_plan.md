# Implementation plan

## Open tasks

### RL-031 — [FEAT] Write the library folder from the dev server

- Dependency: None.
- Why: The owner wants all motion to come from one place, the library folder (`~/Documents/RigLab/`), with no second source. Today the editor seeds new documents from the folder but saves to separate `.riglab.json` files, so motion authored in the editor never reaches the folder, and the wardrobe, which reads only the folder, never plays it. A browser page cannot write the folder itself, so the dev server that already reads and watches it must write it. This task builds that write path and proves it safe, with no editor change yet.
- Scope: Add a pure `planLibrarySave(files, { rig, animations })` in `src/library/save.ts`. The rig goes to the path the config's `rig` line maps. Each animation goes to its mapped path, and a new one goes to `animations/<name>.anim.json`. The config's `animation` lines are rewritten in editor order at the first animation line's position, or appended when there is none. Every other line and comment stays as it was. A removed or renamed animation's old file is removed. A target path that another entry maps, or that two animations share, is refused. Run the loader on the merged files and refuse the save, writing nothing, if the library would not load, for example a rig edit that leaves a skin without a part for a new slot. The library plugin serves `POST /__riglab/library` on the dev server only. It accepts only a same-origin request: an `Origin` equal to the server's own, `Sec-Fetch-Site: same-origin` when the browser sends it, `Content-Type: application/json`, and a body of 2 MiB or less. It refuses while the placeholder library is in use, which stays read-only. Before writing, it copies the previous version of every changed or removed file into `backups/<UTC timestamp>/` under the same relative path. It writes each file through a temporary file and a rename, keeps every write and removal inside the folder's real path, and writes `config.txt` last. It answers with the written and removed paths and the backup folder, or with the loader's errors. Watcher events for the files the plugin just wrote do not trigger Vite's full reload. Instead the plugin sends a `riglab:library-saved` event carrying the save's ID. Changes made outside RigLab still reload every page, as they do now.
- Non-goals: Any editor or wardrobe change (RL-032), writing skins, weapons, palettes or holds, pruning `backups/`, and a production-build or non-dev-server write path.
- Acceptance: Unit tests cover the plan: an edited animation keeps its path; a new animation lands in `animations/`; a renamed or deleted one removes its old file and line; config comments, blank lines and the order of other lines are kept; the rig goes to its mapped path; path collisions are refused. A save that breaks the library is refused with the loader's errors and writes nothing. Request tests refuse a missing or foreign `Origin`, a cross-site `Sec-Fetch-Site`, a non-JSON body, an oversized body and the placeholder library. On a temporary folder, a save writes the files, puts the previous versions under `backups/<timestamp>/`, leaves no temporary files, and reports exactly what changed. The plugin's own writes send `riglab:library-saved`, and an outside edit still sends a full reload. `npm run check` passes.
- Validation: Pinned `npm ci`, focused library tests, `npm run check`, `npm run audit:dependencies`, `check:patch`, `git diff --check`, a live `curl` save against a worktree dev server on a temporary `RIGLAB_LIBRARY` copy, and exact-head CI.
- Authorities: `src/library/plugin.ts`, `src/library/folder.ts`, `src/library/config.ts`, `src/library/load.ts`, `src/format/document.ts`, `src/format/animation.ts`, `src/format/rig.ts`, `docs/ARCHITECTURE.md`, and owner direction on 2026-10-13.

### RL-032 — [FEAT] Make the library folder the editor's only source of motion

- Dependency: RL-031.
- Why: With the write path in place, the editor must read and save only the library folder. The owner chose "Save writes the folder": the editor always edits the library's rig and animations. Save writes them back, and separate document files go away, so no second copy of motion exists.
- Scope: The editor starts from the library's rig and animations, as a new document does today. Save (⌘S / Ctrl+S, and the toolbar button) posts the current rig and animations to `POST /__riglab/library`. On success it marks them saved and the status names the library and the files written. On refusal the status shows the first error and how many more there are. Without the dev server, the status says Save needs `npm start`. The toolbar title shows the library label in place of a file name, with the unsaved dot. Remove New, Open and Save As, their shortcuts, `src/editor/files.ts`, the document open and save code in `src/app/useFileCommands.ts`, and the reducer's `new` and `open` actions. `riglab.document` stays as the editor's in-memory model and validator, but no document file is read or written. The Export panel keeps exporting bundles and the Hexframe rig and clip. Its bundle import still replaces the editor's rig and animations, and Save then writes them to the folder. The editor ignores `riglab:library-saved` for its own save. For another tab's save or an outside change, it reloads when it has no unsaved changes, and otherwise warns in the status that the folder changed. The wardrobe reloads on `riglab:library-saved`. Update the README (shortcuts, the editor's file model, the library section) and `docs/ARCHITECTURE.md`.
- Non-goals: Saving skins, weapons, palettes or holds; migrating or deleting existing `.riglab.json` files on disk; autosave; multi-library switching; and changing the export bundle or Hexframe export formats.
- Acceptance: Unit tests cover the following. The shortcut map has no New, Open or Save As. Save dispatches `saved` on success and an error status on refusal or a network failure. Reload handling ignores its own save ID, reloads a clean editor, and warns a dirty one. A headless Chrome pass runs against `npm start` on a temporary `RIGLAB_LIBRARY` copy of the real folder. Posing a key and pressing ⌘S changes that animation's file on disk. `config.txt` keeps its other lines, and the previous file lands in `backups/`. The editor keeps its mode, animation and frame, and its title shows the library with no unsaved dot. An open wardrobe tab reloads and plays the new pose. Renaming and deleting an animation update the folder. A rig edit the skins cannot follow is refused, and the folder is unchanged. The toolbar shows no New, Open or Save As, and there are no console errors. `npm run check` passes.
- Validation: Pinned `npm ci`, focused editor and wardrobe tests, `npm run check`, `npm run audit:dependencies`, `check:patch`, `git diff --check`, the headless Chrome pass, and exact-head CI.
- Authorities: `src/app/App.tsx`, `src/app/Toolbar.tsx`, `src/app/useFileCommands.ts`, `src/editor/files.ts`, `src/editor/shortcuts.ts`, `src/editor/state.ts`, `src/editor/types.ts`, `src/editor/core.ts`, `src/editor/templates.ts`, `src/wardrobe/main.tsx`, the RL-031 save endpoint, `README.md`, `docs/ARCHITECTURE.md`, and owner direction on 2026-10-13.
